- 新增 11 项后端用例（含参数化场景）：图片渲染、按页转写与检索接通、缓存跳过、失败重试、服务重启、人工修正并发保护、停止后续页面、识别期间禁止删除、页码和批量上限、登录／密钥校验、图片请求结构、错误响应隐藏及截断结果不覆盖原文。
- 新增浏览器流程：无文字 PDF → 出题提示先识别 → 从选中页码打开 OCR → 识别进度 → 原图与 LaTeX 对照 → 重复识别缓存命中且 0 tokens → 人工修正 → 手机布局 → 检索与生成测验。该流程模拟视觉响应，不衡量识别准确率。
- 独立真实接口测试：使用自行编写并由 KaTeX 渲染的中文数学测试页，调用 `deepseek-flash`，返回 319 个字符、1257 tokens，JSON 校验通过。人工对照确认交集概率公式、正态密度的分式／根号／指数、定积分上下限、2×2 矩阵和有限求和的 LaTeX 转写一致。
- 真实测试未发送用户教材，只发送自制测试图。用户教材仅在本机检查了扫描结构和单页渲染。自动审批未允许其具体页面外发，本次未实测该教材的识别准确率。

## OCR「识别结果格式异常」修复

- 旧代码把整页 LaTeX 放在模型生成的 JSON 字符串中，再用 Pydantic 解码。回归测试复现：单反斜杠的 `\cup` 会触发无效 JSON；`\frac` 的 `\f` 还可能被 JSON 静默解释成换页控制字符。旧异常分支还将缺失用量等不同原因合并成同一条提示。
- 改为接收带首尾标记的 Markdown／LaTeX 正文，不再要求模型为公式进行 JSON 字符串转义。保留截断检查和原内容保护，明确区分空正文、结构异常、内容过长、缺失结束标记等；允许最外层完整 Markdown 代码围栏。
- 用量元数据缺失不再影响正文保存；接口已报告的格式失败用量计入任务，终端仅记录固定诊断信息，不输出模型正文或密钥。
- 全部 60 项后端用例通过。新增用例包含旧问题复现、集合／分式／矩阵及希腊字母的逐字符保存、外层围栏、空页与空返回区别、异常类型、失败用量、重试成功后入库及日志不泄露正文。
- 重新通过浏览器 OCR → 原图校对 → 缓存复用 → 人工修正 → 出题流程，含桌面和手机视口。本次未修改前端产品代码。
- 使用自制中文公式测试图再次调用真实接口，新协议成功返回 321 字符、1249 tokens；矩阵换行、分式、积分和求和符号保留。
- 增加自制密集中文公式页的真实接口测试：返回 1582 字符、2247 tokens，页尾测试编号完整，无异常控制字符。人工对照检查了集合差／并／交／补、连并连交、条件概率、分段函数、积分、希腊字母、组合数、三阶矩阵和极限表达式，转写内容一致。
- 未保留用户失败时的原始模型响应，当前也无法访问其第 18 页原文件，因此无法追溯确定当次具体触发条件；本修复覆盖已复现的转义缺陷，并补充可区分的诊断信息。真实调用均使用自制材料。
